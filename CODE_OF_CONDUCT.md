# Community Code of Conduct

Livariant should be a place where people can ask basic questions, challenge technical decisions, report problems, and discuss ideas without being mocked for their experience level.

## Expected behavior

When you take part in Livariant Issues or Discussions:

- treat other people with respect;
- assume that experience levels differ;
- explain disagreements with reasons and evidence;
- criticize ideas and implementations, not the person behind them;
- keep technical discussion focused on the topic;
- avoid harassment, discrimination, threats, sexualized conduct, personal attacks, and deliberate disruption;
- do not publish another person's private information;
- do not pressure people to disclose private project data, credentials, or security details publicly.

Beginners are welcome. A question is not invalid because the person asking it is new to AI-assisted development, Git, Node.js, Claude Code, Codex, or Livariant.

## Security discussions

Do not post vulnerability details, exploit instructions, credentials, or sensitive project information in public Issues or Discussions.

Follow [SECURITY.md](SECURITY.md) for security reporting.

## Moderation

Maintainers may edit, hide, lock, or remove content that violates these guidelines. Repeated or serious violations may result in participation restrictions where GitHub provides those controls.

Moderation decisions should be based on behavior in the Livariant community, not on whether someone agrees with the maintainer's technical opinion.

## Scope

These guidelines apply to Livariant's repository community spaces, including Issues, Discussions, pull request conversations, and other project-managed communication surfaces.

## Reporting a conduct problem

If a community interaction needs moderation, contact the maintainer through an appropriate non-public contact path when one is listed in the repository profile or project documentation. Do not use the security vulnerability channel for ordinary moderation disputes unless the report itself involves a security or privacy risk.

This project-specific code of conduct is intentionally concise. It can be expanded if the community grows and additional moderation procedures become necessary.
