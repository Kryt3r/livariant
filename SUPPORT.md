# Getting help with Livariant

Use the channel that matches what you need. This helps questions reach the right place and keeps security reports out of public threads.

## I have a question about using Livariant

Use **GitHub Discussions -> Q&A**.

Good examples:

- I am new to AI-assisted coding. Where should I start?
- How do I use Livariant with an existing Claude Code project?
- What does `livariant resume` give me?
- Is a specific workflow supported in the current Preview?

Before opening a question, check the [README](README.md), [installation guide](docs/installation.md), and [Quickstart](docs/quickstart.md).

## I found a reproducible bug

Open a **Bug report** under GitHub Issues.

Please include the Livariant version, operating system, Node.js version, the command you ran, what you expected, what happened instead, and a minimal reproduction when possible.

Do not include secrets or private project data.

## I found a documentation problem

Open a **Documentation problem** under GitHub Issues.

This includes unclear instructions, broken links, incorrect examples, missing beginner explanations, and differences between the English and German user guides.

## I have an idea or feature suggestion

Use **GitHub Discussions -> Ideas**.

Ideas are better suited to discussion before they become implementation work. This also keeps the issue tracker focused on reproducible product and documentation problems.

## I want to show what I built

Use **GitHub Discussions -> Show and tell**.

## I think I found a security vulnerability

Do not post exploit details in a public Issue or Discussion.

Read [SECURITY.md](SECURITY.md) and use the private vulnerability-reporting path described there once it is enabled for the public repository.

If the private security path is unavailable, do not publish exploit details just to get attention. Follow the fallback guidance in `SECURITY.md`.

## I want to contribute code

External code contributions are not currently accepted for incorporation while contributor-rights terms are being finalized.

Bug reports, documentation feedback, questions, and design discussion are welcome. See [CONTRIBUTING.md](CONTRIBUTING.md) for the current contribution boundary.

## Quick routing map

| Need | Use |
| --- | --- |
| Usage question | Discussions: Q&A |
| Feature or design idea | Discussions: Ideas |
| Reproducible product bug | Issues: Bug report |
| Documentation error | Issues: Documentation problem |
| Security vulnerability | Private security reporting |
| Share a project or workflow | Discussions: Show and tell |
| Code contribution | Currently gated |
